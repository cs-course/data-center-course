> 目标规模：约 1000 行 MARP（新建，论文转讲稿为主）

## 四、两讲之间的衔接与差异定位

> v3.1 更新：M2 与 M3 的关系从"保障↔检测"（原 M3 AIOps）调整为"系统层↔设备层"（新 M3 闪存存储）

| 维度 | M2《性能预测技术与服务质量保障》 | M3《闪存存储系统设计：从介质特性到服务质量》 |
|------|------|------|
| 核心问题 | 如何在**系统层**用预测保障 QoS？ | 如何在**设备层**用预测优化 SSD？ |
| 技术视角 | 系统层：负载预测 + 闭环调控 | 设备层：访问模式预测 + 机制优化 |
| 研究项目 | **同一项目**——分布式存储系统性能预测 | **同一项目**——闪存存储系统设计 |
| 三挑战结构 | 干扰 → 长尾 → 预测 | 映射 → 缓存 → 公平性 |
| 预测方法 | 控制论 / 约束优化 / 机器学习 | 静态增强 / 多因子+DRL / 协作感知 |
| 共享论文 | CoFS（约束优化视角）、Fair Will Go On（公平性调控）、Graph3PO（ML 预测） | CoFS（设备层公平调度）、Fair Will Go On（协作感知机制）、Graph3PO（对象存储 QoS） |
| 演示主体 | 性能指标预测（MA/ARIMA/ML 对比） | 缓存替换策略模拟器（LRU/FIFO/多因子/DRL 对比） |
| 与 object-storage.md 关系 | 现象层（长尾/预测）首讲在 OS；M2 单向避让，挑战二重构为 SLO 违约归因+错误预算，挑战三回指 OS 排队论建模 | 共享 SSD 参考文献（L1493-1597）和论文背景图（OS 为引子，M3 为主体） |
| 与 data-center-intro.md 关系 | 深化"集中使用"和"平台软件"两节 | 深化"先进存储"（OC-SSD/ZNS-SSD）和延迟数据 |

两讲构成"**系统层 ↔ 设备层**"的对偶关系：M2 在分布式存储系统层面引入预测方法保障服务质量，M3 在 SSD 设备层面引入预测方法优化存储机制。两者服务于同一个研究项目——分别在系统层和设备层引入预测方法加以优化。若先后使用，M3 的设备层机制可自然铺垫 M2 的系统层挑战（"SSD 内部的公平性调度，在分布式层面就变成了 QoS 保障问题"）；反之，M2 的系统层视角也可为 M3 的设备层优化提供上层目标（"系统层需要的 SLO 承诺，最终要靠设备层的机制来落地"）。
